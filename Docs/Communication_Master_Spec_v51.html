3. TOECIM <-> Console 통신

TOECIM(CIM)과 Console 간의 JSON 기반 TCP 직접 통신 프로토콜입니다.

1. Communication Method

  • Protocol: TCP Socket (Engion.Net Library)
  • Data Format: JSON (Newtonsoft.Json)
  • Network: CIM Server (Port 7000) <-> Console Client

2. JSON Data Format (Example)

{
  "WaitResponse": true,
  "ToCIM": {
    "Command": "LoadReadyDone",
    "eqpStatus": "RUN",
    "GlassPanelJudgeA": "G",
    "GlassPanelJudgeB": "G",
    "RecipeItem": { "RecipeName": "Lucid34" }
  },
  "ToConsole": {
    "Command": "None",
    "ResultOK": true
  }
}

3. Main Command List (JSON Commands)

Direction Command Description
Console → CIM LoadReadyDone 설비 로드 준비 완료 보고 (S6F61 유발)
InspectDone 검사 완료 보고 (S6F73, S6F63 유발)
Alarm 알람 및 오류 발생 보고
SendData 실시간 설비 상태 업데이트
CIM → Console LoadRecipe 레시피 변경 요청 (ECS Simulator S7F61로부터)
Pause 공정 일시정지 요청 (ECS Simulator S2F99 RCMD:PAUSE로부터)
EQStatusDataReq 동기화를 위한 현재 설비 상태 요청

4. Console <-> TSP 통신

Console과 TSP 검사 엔진 간의 직접 TCP/IP 통신 프로토콜입니다.

1. Packet Structure (STX/ETX Format)

Offset Field Type Description
0 STX Byte 텍스트 시작 (0x02)
1 Header.Cmd Short 명령어 ID (예: 0x31: ModelChange)
3 Header.Len Short 본문 데이터 길이
5 Body Data Binary 명령어별 상세 파라미터
N ETX Byte 텍스트 종료 (0x03)

2. Main Command List

ID Command Name Description
0x31 ModelChangeReq 모델명 및 보드 사용 여부 동기화 (1,0)
0x32 TestStartReq GlassID 및 PanelID를 포함한 검사 트리거
0x53 TestStartEndRes 검사 완료 보고 알림
0x70 PingConnection 통신 상태 점검 (하트비트)

2. 상세 분석 내용

HSMS (SECS-II) 분석

  • Device ID: 0 사용 (표준값)
  • S6F73/S6F63: Unload 및 공정 완료 보고 시 PNLIF(A[2000]) 판정 데이터 포함 필수.
  • S2F17: 장비(TOECIM)가 주기적으로 Time Sync 요청 권장.

MELSEC (PLC) 분석

  • Address 체계: B(Bit), W(Word) 기반 상대 주소 사용.
  • Handshake: LoadReq -> LoadEnable -> LoadStart -> LoadDone의 4-Step 시퀀스 기반.
  • Heartbeat: Link Test Bit를 통한 상호 생존 확인(Liveliness) 필수.
